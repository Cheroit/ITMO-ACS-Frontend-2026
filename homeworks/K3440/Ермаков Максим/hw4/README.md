# Домашняя работа 4 «На кухне»

**Ермаков Максим, K3440. Вариант 5:** сервис для обмена рецептами и кулинарных блогов.

В копии сайта из ДЗ3 я объединил SVG-значки колпака, меню и закрытия в один спрайт. Сайт использует HTML, CSS, Bootstrap и обычный JavaScript. Данные загружает учебный API на JSON Server.

## Запуск

Нужен Node.js версии 22 или новее. Откройте терминал в папке `hw4` и выполните команды:

```sh
npm ci
npm start
```

Откройте [http://localhost:3000](http://localhost:3000).

Сервер раздаёт страницы из `public` и отвечает на запросы к `/api`.

Если порт занят, можно выбрать другой:

```sh
PORT=3001 npm start
```

Для остановки сервера нажмите `Ctrl+C`. После повторного запуска созданные аккаунты, рецепты и комментарии сохранятся.

## SVG-спрайт

В `public/assets/images/icons.svg` три элемента `symbol` с идентификаторами `chef-hat`, `menu` и `close`. На странице `use` ссылается на нужный символ по его идентификатору.

```html
<svg class="svg-icon" aria-hidden="true" focusable="false">
  <use href="assets/images/icons.svg#chef-hat"></use>
</svg>
```

`currentColor` берёт цвет из CSS, поэтому значки подстраиваются под тему. Кнопки меню и закрытия сохраняют текстовые подписи в `aria-label`. Сам спрайт также служит значком вкладки благодаря внутренней ссылке на колпак.

## Темы

- В шапке есть поле «Тема». На телефоне оно доступно в раскрытом меню.
- «Системная» использует настройку светлой или тёмной темы устройства и реагирует на её смену. «Светлая» и «Тёмная» позволяют выбрать палитру вручную.
- `public/js/theme.js` сохраняет выбор в `localStorage` и устанавливает атрибут `data-bs-theme` на `<html>`. Скрипт загружается перед таблицей стилей, чтобы сразу применить выбранную палитру.
- В `public/css/style.css` общие цвета заданы в `:root`, а селектор `:root[data-bs-theme='dark']` переопределяет их для тёмной темы. Bootstrap по тому же атрибуту переключает оформление полей и других элементов.

Для проверки выберите тёмную тему, откройте каталог и обновите страницу. Затем переключитесь на светлую или системную тему. Обе палитры можно посмотреть на форме входа, в карточке рецепта и в открытой заметке.

## Что изменилось по сравнению с ЛР1

- Рецепты, авторы и статьи загружаются с сервера.
- Регистрация создаёт пользователя в базе. При входе сервер действительно проверяет email и пароль.
- Сервер возвращает JWT-токен. Закрытые запросы отправляются с заголовком `Authorization: Bearer ...`.
- Публикации, комментарии, сохранения, лайки и подписки записываются в базу через API.
- Сохранённые рецепты и подписки доступны только владельцу. Сервер проверяет токен и принадлежность записи, даже если вручную изменить запрос.
- Комментарии, новые рецепты и количество лайков видны другим пользователям при загрузке страницы.
- Для запросов предусмотрены сообщения о загрузке и ошибках. Кнопки отправки блокируются на время запроса. При истёкшей сессии сайт предлагает войти заново.

Сессия этой копии хранится под ключом `nk3-session`. Флажок «Запомнить меня» выбирает `localStorage` или `sessionStorage`. Настройка темы хранится отдельно под ключом `na-kuhne-theme`. Пароль хранится на сервере в виде bcrypt-хеша.

Видео по-прежнему представлено заглушкой «Видео будет добавлено позже». Фото при публикации выбирается из готовой подборки.

## Структура проекта

```text
hw4/
  server.js          — запуск JSON Server, маршруты, проверка доступа и данных
  seed.json          — исходные рецепты, авторы, статьи и комментарии
  db.json            — рабочая база, создаётся автоматически и исключена из Git
  package.json       — зависимости и команда запуска
  package-lock.json  — точные версии установленных зависимостей
  public/
    *.html           — семь страниц сайта
    css/style.css    — оформление и адаптивность
    js/theme.js      — выбор темы и сохранение настройки
    js/api.js        — fetch, сессия и обработка ошибок HTTP
    js/common.js     — общие карточки, авторы, лайки, сохранения и подписки
    js/auth.js       — формы входа и регистрации
    js/recipes.js    — главная, каталог и фильтры
    js/recipe.js     — страница рецепта и комментарии
    js/profile.js    — кабинет и публикация рецепта
    js/blogs.js      — статьи и карточки кулинаров
    assets/          — SVG-спрайт, фотографии и шрифт
    vendor/          — Bootstrap и Bootstrap Icons
```

`db.json` копируется из `seed.json` только при первом запуске. Последующие запросы изменяют рабочую базу, а исходные данные остаются в `seed.json`. `node_modules` также исключён из Git.

## Основные запросы

| Запрос | Что делает | Доступ |
| --- | --- | --- |
| `POST /api/register` | Создаёт аккаунт и возвращает токен | Гость |
| `POST /api/login` | Проверяет пароль и возвращает токен | Гость |
| `GET /api/authors` | Возвращает имена и описания авторов | Все |
| `GET /api/recipes` | Возвращает рецепты | Все |
| `GET /api/recipes/:id` | Возвращает конкретный рецепт | Все |
| `POST /api/recipes` | Публикует рецепт | Вошедший пользователь |
| `GET /api/articles` | Возвращает статьи | Все |
| `GET /api/comments?recipeId=pasta` | Возвращает комментарии к рецепту | Все |
| `POST /api/comments` | Добавляет комментарий | Вошедший пользователь |
| `GET /api/likes` | Возвращает лайки для подсчёта | Все |
| `GET /api/saved` | Возвращает свои сохранения | Вошедший пользователь |
| `GET /api/following` | Возвращает свои подписки | Вошедший пользователь |
| `POST /api/likes`, `/api/saved`, `/api/following` | Добавляет действие | Вошедший пользователь |
| `DELETE /api/likes/:id`, `/api/saved/:id`, `/api/following/:id` | Отменяет своё действие | Владелец записи |

Тип блюда и сложность передаются в параметрах запроса, например:

```text
/api/recipes?type=Супы&difficulty=Легко
```

Поиск по названию и продуктам уточняется в `recipes.js` после ответа сервера. Здесь же проверяются все ингредиенты через запятую и приводятся к одному виду буквы «ё/е».

## Как читать код

Начните с `public/js/api.js`: функция `apiRequest()` отправляет запрос, добавляет токен, превращает объект в JSON и проверяет ответ. Затем посмотрите `auth.js`: форма вызывает эту функцию для `/register` или `/login` и сохраняет полученную сессию.

В `common.js` функция `initializeApp()` загружает общие данные. Скрипты страниц ждут её через `await appReady`. Например, `loadRecipe()` в `recipe.js` затем запрашивает конкретный рецепт и его комментарии и заполняет HTML.

В `server.js` сначала подключаются статические файлы и JSON-парсер, затем маршруты авторизации и проверки токена, после них — проверки владельца и полей формы. Последним подключается роутер JSON Server, который читает и изменяет базу.

Версии `json-server` **0.17.4** и `json-server-auth` **2.1.0** зафиксированы для совместимости с подходом из лекции. Этот проект использует учебное моковое API.

## Проверка

1. Зарегистрируйте пользователя. Проверьте несовпадающие пароли и повторную регистрацию с тем же email.
2. Выйдите. Попробуйте неверный пароль, затем войдите с правильным.
3. В каталоге выберите «Основные блюда», «Легко», ингредиенты `томаты, чеснок`. Останется паста. Проверьте пустой поиск и сброс фильтров.
4. Сохраните пасту, поставьте лайк, подпишитесь на автора и добавьте комментарий. Обновите страницу.
5. Проверьте сохранения и подписки в кабинете. Отмените действия и убедитесь, что счётчики обновились.
6. Опубликуйте рецепт. Он должен появиться в своих публикациях, общем каталоге и открываться по своей ссылке.
7. Откройте сайт в другом браузере или приватном окне. Новая публикация, комментарий и лайк будут видны, а личные сохранения потребуют входа.
8. Остановите и запустите сервер снова: данные останутся в `db.json`.
9. В инструментах разработчика откройте вкладку Network и фильтр Fetch/XHR: там видны `GET`, `POST`, `DELETE`, данные запросов и ответы сервера.
10. Проверьте узкую ширину окна: меню раскрывается кнопкой, форма рецепта прокручивается внутри модального окна.
